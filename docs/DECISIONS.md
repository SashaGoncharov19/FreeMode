# Decisions

Decided things and open questions, in one place. A task may only be `ready` when every decision it depends on
is in the "Decided" table. An agent that meets an undecided question while working adds it to "Open" with a
recommended default, takes the default, and writes a Log line in the task (`docs/agents/workflow.md`).

Format of an entry: what was decided, why, what was rejected, date. Keep entries short; the reasoning that needs
more than a paragraph lives in the area document and is linked.

| D-09 | **Server gamemode scripts run in Bun, in a separate process next to the .NET engine; client scripts stay on ClearScript V8 inside the game; Bun is also the build tool for both.** The engine (networking, sync relay, streaming, entities, validation, file server) stays C#; the Bun runtime hosts the resources and talks to the engine over a local socket with a binary protocol, a state mirror (entity state pushed to Bun at 10 Hz, so reads are local) and one-way setters; only calls that need an engine answer wait. The owner wants Bun's built-in APIs (`Bun.sql`, `Bun.redis`, `Bun.s3`, fetch, WebSocket) without third-party modules. The spike (T-006 stage 1, 5 Sept) measured the bridge: 2.0 M one-way calls/s at 0.5 µs, round trip p50 6 µs / p99 13 µs (Unix socket), mirror of 1000 players at 10 Hz 1.8 % engine / 3.5 % Bun of a core — targets met, stage 2 goes ahead; Unix socket on Linux, loopback TCP on Windows. Rejected: Bun inside the game process (impossible), a sidecar for client scripts (natives are called per frame). | 2026-09-04, confirmed 2026-09-05 |

Runtime mounting without restart (RAGE `fiDevice` hooks) is a later spike (T-021), not the MVP. | 2026-09-04 |
