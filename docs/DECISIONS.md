# Decisions

Decided things and open questions, in one place. A task may only be `ready` when every decision it depends on
is in the "Decided" table. An agent that meets an undecided question while working adds it to "Open" with a
recommended default, takes the default, and writes a Log line in the task (`docs/agents/workflow.md`).

Format of an entry: what was decided, why, what was rejected, date. Keep entries short; the reasoning that needs
more than a paragraph lives in the area document and is linked.

| D-09 | **Server gamemode scripts run in Bun, in a separate process next to the .NET engine; client scripts stay on ClearScript V8 inside the game; Bun is also the build tool for both.** The engine (networking, sync relay, streaming, entities, validation, file server) stays C#; the Bun runtime hosts the resources and talks to the engine over a local socket with a binary protocol, a state mirror (entity state pushed to Bun at 10 Hz, so reads are local) and one-way setters; only calls that need an engine answer wait. Rejected: Bun inside the game process (impossible), a sidecar for client scripts (natives are called per frame). | 2026-09-04, confirmed 2026-09-05 |

| D-14 | **Session crypto (T-009): X25519 (client ephemeral, server static key in `server.key`) + HKDF-SHA256 → one 32-byte key per session; AES-256-GCM per Lidgren message with a per-direction counter nonce (8 bytes on the wire) and a 128-message replay window; BouncyCastle.Cryptography 2.6.2 on the .NET Framework client, System.Security.Cryptography.AesGcm on the .NET 10 server and bot; pinning through the connect string (`host:port#key`) and later the master list; `RequireEncryption` default true.** | .NET Framework 4.8 has no AES-GCM and no X25519; BouncyCastle is pure managed and works in the game's second AppDomain. The server relays every sync packet once per recipient, so it gets hardware AES. Forward secrecy is not a goal for the MVP (a static server key keeps the handshake to one round trip inside the existing hail); the message counter replaces Lidgren's unauthenticated sequence numbers for replay protection. Rejected: DTLS (no library on net48 without native code), Lidgren's XTEA (no authentication, shared static key). | 2026-09-05 |
| D-13 | **RPC payloads are one JSON value per request and per response inside protobuf (`Shared/Rpc/RpcMessages.cs`), names are global across resources (prefix them with the resource name), limits fixed in code: 64 KB per payload, 30 requests/s per player, 10 s default / 60 s maximum timeout; errors are a code (`timeout`, `denied`, `unknown`, `rate`, `handler`, `size`, `invalid`, `disconnected`) plus a message, never a stack trace.** On the client the promises live in a JavaScript helper inside the script's engine, so continuations always run on the script thread. | JSON needs no per-call schema on three sides (C#, ClearScript, Bun/CEF) and stays debuggable; MessagePack would save bytes but RPC is not the bandwidth-critical path (sync is). Global names keep one registry and let a CEF page or client script call any resource's handler without knowing where it lives. ClearScript's Task→Promise conversion was rejected because it resolves promises on the completing thread, and the game's natives must be called on the script thread. | 2026-09-05 |
| D-12 | **M1 priorities: platform first (.NET 10, TS typings, Bun bridge spike, RPC), then UI (CEF loader and menu, launcher GUI, master list).** Scale (load harness, interest management) is M2; gameplay (sync instrumentation, voice) M3. | 2026-09-04 |
